# Diagnóstico Restaurante — Levantamiento de necesidades

> Etapa **previa** a adaptar el sistema SaaS a restaurantes. **No** hay código ni adaptación aquí — solo el instrumento de diagnóstico y su análisis.

## Documentos
1. [`FORMULARIO_DIAGNOSTICO.md`](./FORMULARIO_DIAGNOSTICO.md) — el formulario (18 secciones, 20–30 min), en formato `Sección | Pregunta | Tipo | Opciones | Condición`, listo para portar a Google Forms / Typeform / formulario web.
2. [`MATRIZ_ANALISIS.md`](./MATRIZ_ANALISIS.md) — matriz interna para convertir dolores en decisiones de producto (dolor → módulo SaaS → automatización → prioridad), con catálogo de mapeo y regla de priorización.
3. [`RESUMEN_EJECUTIVO_PLANTILLA.md`](./RESUMEN_EJECUTIVO_PLANTILLA.md) — plantilla del informe para la dirección (perfil, top 5 dolores, quick wins, gap analysis, KEEP/REFACTOR/NEW).

## Flujo de uso
1. Aplicar el **Formulario** al restaurante (entrevista o autollenado).
2. Volcar respuestas en la **Matriz** (una fila por dolor).
3. Redactar el **Resumen ejecutivo** con las conclusiones.
4. Recién entonces decidir la **adaptación** del SaaS.

Orden global: `LEVANTAR → IDENTIFICAR DOLORES → PRIORIZAR → MAPEAR vs SaaS → GAPS → DISEÑAR ADAPTACIÓN → IMPLEMENTAR`.
